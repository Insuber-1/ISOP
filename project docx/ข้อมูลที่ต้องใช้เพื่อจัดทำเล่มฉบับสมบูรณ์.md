# ข้อมูลโครงงานและรายการที่ต้องยืนยัน

## ข้อมูลที่ได้รับจากผู้จัดทำ

- **ชื่อโครงงานภาษาอังกฤษ:** Intelligent Server Operations Platform
- **ชื่อโครงงานภาษาไทย:** ระบบปฏิบัติการและบริหารจัดการเครื่องแม่ข่าย
- **ผู้จัดทำ/เจ้าของโครงงาน:** วัชชิรปกรณ์ มีชัย และ สุวัชรชาติ อาษาสร้อย
- **อาจารย์ที่ปรึกษา:** อาจารย์อัษฎาวุธ เพชรพรรณ
- **แนวคิด:** ช่วยผู้ดูแลระบบเฝ้าระวังและจัดการเครื่องแม่ข่าย ลดการเฝ้าหน้าจอและการรีโมตเข้าไปแก้ปัญหาด้วยตนเอง รองรับการจัดการผ่าน YAML/Docker Compose การติดตาม CPU/RAM/Disk การแจ้งเตือน การเก็บ log การสำรองข้อมูล และหน้าเว็บสำหรับเข้าดูจากระยะไกล

## คำอธิบายโครงงานฉบับเรียบเรียง (รอตรวจยืนยันกับผู้จัดทำ)

Intelligent Server Operations Platform เป็นโปรแกรมช่วยผู้ดูแลระบบติดตามและบริหารจัดการเครื่องแม่ข่ายและ Docker container จากจุดเดียว โปรแกรมรวบรวมการใช้ CPU หน่วยความจำ และพื้นที่จัดเก็บ พร้อมแสดงสถานะและแนวโน้ม บันทึกค่าการทำงานและเหตุการณ์เพื่อให้ตรวจสอบย้อนหลังได้ เมื่อตรวจพบค่าทรัพยากรสูงผิดปกติ ระบบจะแจ้งเตือนและเรียกใช้การดำเนินการแก้ไขตามเงื่อนไขที่กำหนด ผู้ดูแลสามารถนำเข้าไฟล์ YAML/Docker Compose เพื่อจัดกลุ่มและจัดการบริการที่เกี่ยวข้อง รวมถึงสั่งงาน container ผ่านโปรแกรมหรือแดชบอร์ดบนเว็บที่มีระบบเข้าสู่ระบบ โปรแกรมยังมีการสำรองไฟล์ตั้งค่าที่เกี่ยวข้องตามช่วงเวลาที่กำหนด ทั้งนี้ ความสามารถและขอบเขตการสำรองข้อมูลขึ้นกับการตั้งค่าของผู้ใช้และไฟล์ที่ระบบเลือกสำรอง

คำอธิบายนี้ตั้งใจหลีกเลี่ยงการกล่าวว่าโปรแกรม “วิเคราะห์หาสาเหตุราก” หรือ “สำรองข้อมูลทั้งเครื่องแม่ข่าย” เพราะยังไม่พบหลักฐานในโค้ดปัจจุบันว่ารองรับสองความสามารถนั้น

## สิ่งที่ตรวจพบในโค้ดปัจจุบัน ซึ่งควรเขียนให้ตรงตามจริง

- การตรวจจับความผิดปกติของ CPU/RAM/Disk ใช้ค่าเฉลี่ยเคลื่อนที่แบบ EMA และเกณฑ์เข้า/ออกจากสถานะผิดปกติ ไม่พบการฝึกโมเดล machine learning ในโมดูล `brain.py` จึงควรอธิบายว่าเป็นกลไกวิเคราะห์/ตรวจจับอัตโนมัติ หรือระบุชัดว่าเป็นกฎเชิงกำหนด หากสถาบันกำหนดให้ใช้คำว่า AI ควรให้อาจารย์ที่ปรึกษาตรวจถ้อยคำ
- เมื่อเข้าเงื่อนไขบางอย่างมี action อัตโนมัติ เช่น จัดการ cache, ลบไฟล์ชั่วคราว หรือจัดการ process ที่ใช้ CPU สูง; โปรดยืนยัน action ที่ต้องการนำเสนอและวิธีป้องกันการปิด process ที่จำเป็น
- การอ่าน CPU/RAM/Disk แบบแยก server ในแดชบอร์ดอาศัย Docker container ตามคำอธิบายในโค้ด ไม่ควรสรุปว่าตรวจเครื่องแม่ข่ายทุกชนิดได้ เว้นแต่มีการทดสอบรองรับ
- การนำเข้า YAML ใช้ไฟล์ Docker Compose เพื่ออ่านบริการ/จัดการ container ส่วน `docker-compose.yml` ของแอปเองเกี่ยวข้องกับบริการประกอบ เช่น เว็บและ tunnel หากต้องการให้ EXE ยังเปิดคุณสมบัติเหล่านี้ได้ ต้องฝังหรือสร้างไฟล์ดังกล่าวระหว่างทำงาน ไม่สามารถตัดเนื้อหา YAML ที่จำเป็นทิ้งโดยไม่ปรับโค้ด
- โค้ดปัจจุบันแสดงการแจ้งเตือนผ่านหน้าต่างโปรแกรม และแดชบอร์ดเว็บมีการเข้าสู่ระบบ; โปรดยืนยันว่าต้องการรวมเฉพาะการแจ้งเตือนในโปรแกรม หรือมีช่องทางอื่นที่ใช้งานจริงด้วย
- กลไก backup ในโค้ดสร้างไฟล์ ZIP ของแหล่งข้อมูล/ไฟล์ตั้งค่าที่เลือก ไม่ควรเรียกว่า backup ข้อมูลทั้งหมดของ server จนกว่าจะยืนยันขอบเขตและผลการกู้คืน

## ข้อมูลที่ยังต้องใช้เพื่อเขียนรายงานและจัดรูปเล่มให้ครบ

ชื่อหลักสูตร/สาขาที่ผู้จัดทำให้มาและได้นำไปใส่ในปกคือ **วิศวกรรมคอมพิวเตอร์และอิเล็กทรอนิกส์ / วิศวกรรมไฟฟ้า / อุตสาหกรรมและเทคโนโลยี**; ได้จัดวางเป็นสาขาวิชา/สาขา/คณะตามถ้อยคำในเอกสารเดิม

1. **วัน/ปีที่เล่มเสร็จสมบูรณ์** และประวัติผู้เขียนตามรูปแบบคู่มือ (วันเกิด/ที่อยู่/การศึกษา 2 ระดับ) — ส่งเฉพาะข้อมูลที่ต้องการเผยแพร่ในเล่ม
2. **รายละเอียดการทดสอบ:** ระบบปฏิบัติการและสเปกเครื่อง, Docker/บริการที่ใช้, จำนวน container, รูปแบบทดสอบ CPU/RAM/Disk, จำนวนครั้ง, ผลแจ้งเตือนและการแก้ไข, เวลาในการตอบสนอง, ผลทดสอบการเข้าเว็บจากเครือข่ายภายนอก, และผล backup/restore
3. **ผลลัพธ์จริงที่วัดได้** เพื่อเขียนบทคัดย่อและบทที่ 4; หากยังไม่มี ให้ระบุว่าไม่มี แล้วจะเขียนเฉพาะผลการทดสอบที่ทำได้โดยไม่สร้างตัวเลขขึ้นเอง
4. **ขอบเขต YAML และการแก้ไขอัตโนมัติ:** YAML เป็นไฟล์ Docker Compose สำหรับประกาศบริการ หรือมีรูปแบบ config เฉพาะที่กำหนดกฎแก้ปัญหาด้วย? ส่งตัวอย่างที่ลบ password/token/ข้อมูลลับแล้วได้
5. **ขอบเขตการสำรองข้อมูล:** สำรองโฟลเดอร์/ไฟล์ใด เก็บปลายทางที่ใด เก็บกี่ชุด และได้ทดลองกู้คืนหรือไม่
6. **ต้นฉบับส่วนที่ยังขาด:** Abstract ภาษาอังกฤษ, บทที่ 2–5, บรรณานุกรม, ภาคผนวก, ใบรับรอง และข้อมูลประวัติผู้เขียน บทที่ 1 ใช้ไฟล์ย่อยทั้งสามต่อกันตามลำดับ `1.1.docx` → `1.1(1).docx` → `1.2.docx` ตามที่ผู้จัดทำยืนยัน

## เรื่องไฟล์ .bat และ .yml

การส่งมอบจะเป็นไฟล์ EXE เดียว โดยไม่แนบไฟล์ `.bat` หรือ `.yml` แยกต่างหาก (ผู้จัดทำยืนยันแล้ว) YAML มีสองความหมายที่ต้องแยกกัน: (ก) ไฟล์ YAML ที่ผู้ดูแลนำเข้าตามปกติ ซึ่งเป็นข้อมูลตั้งค่าที่ผู้ใช้ยังอาจต้องเลือกใช้ และ (ข) `docker-compose.yml` ที่โปรแกรมใช้เปิดบริการเว็บ/tunnel ของตัวเอง ซึ่งต้องมีใน runtime หากต้องการคุณสมบัตินั้นต่อไป แนวทาง one-file สามารถฝังทรัพยากรที่จำเป็นใน EXE ได้ แต่ไม่ควรลบจนความสามารถหยุดทำงาน
